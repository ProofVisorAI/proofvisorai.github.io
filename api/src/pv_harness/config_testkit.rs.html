1//! Test-support constructors for [`HarnessConfig`], kept OUT of
2//! `config.rs` on purpose: the permissive test
3//! defaults in `for_tests` fooled three independent reviewers,
4//! because a grep for a config default finds the test value in the
5//! same file as the production one. With this file, the production
6//! defaults are the only ones a reader finds in `config.rs`.
7

13    /// # TESTS AND BENCHES ONLY

15    /// The defaults here are DELIBERATELY permissive: `require_identity
16    /// = false`, `require_tool_schema = false`, `enforce_identity_
17    /// scopes = false`, `strict_stage_budget = false`. That posture is
18    /// safe for a test harness but MUST NOT be shipped into a
19    /// production boot path. This module only compiles under
20    /// `cfg(test)` or the `test-support` cargo feature (enabled solely
21    /// by the self dev-dependency), so production artifacts cannot
22    /// even name this function. It is additionally `#[doc(hidden)]` so
23    /// it does not appear in the public API surface (rustdoc, editor
24    /// completion) and cannot be discovered by a future "smoke boot"
25    /// helper looking for a quick config constructor. Any production
26    /// caller must build a `HarnessConfig` explicitly from
27    /// [`Self::from_toml`] so the deliberate posture flags are
