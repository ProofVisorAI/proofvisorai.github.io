Module exchange 

Source
Expand description

RFC 8693 token exchange: exchange an inbound NHI token for a backend-scoped token with narrowed scopes.

The exchange endpoint accepts a form-encoded request containing:

  • grant_type=urn:ietf:params:oauth:grant-type:token-exchange
  • subject_token — the inbound NHI JWT
  • subject_token_type=urn:ietf:params:oauth:token-type:jwt
  • audience — the target backend name
  • scope — requested scopes (space-separated, optional)
  • actor_token / actor_token_type — optional RFC 8693 §2.1 actor: a validated NHI token naming the agent that will act

The issued token preserves the original sub (human principal) and records the acting agents in act, newest first. Without an actor token, act.sub and azp are the subject token’s agent. With an actor token, act.sub and azp are the actor’s agent and the subject’s agent moves one level down (act.act.sub). Scopes are always an intersection, never a union: requested ∩ subject, and additionally ∩ actor when an actor token is present.

build_exchanged_claims
Build exchanged claims from a validated subject token. The resulting token preserves sub (the human), adds a new link to the act chain, scopes to the intersection of requested and subject scopes, and narrows audience to the target backend.
build_exchanged_claims_with_actor
build_exchanged_claims with an optional RFC 8693 actor token. The actor must be an undelegated token; its scopes further narrow the result, its agent becomes act.sub and azp, the subject’s agent becomes act.act.sub, and the delegation depth grows by two.
