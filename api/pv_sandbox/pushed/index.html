Module pushed 

Source
Expand description

Console-pushed policy, layered on top of the local sandbox config.

The console publishes a policy bundle; pvctl console-sync --pull-policies hands it to the daemon, which compiles it into one PushedRules value and swaps it into the running crate::Sandbox. Pushed rules only ever add restrictions:

  • budgets are merged with [BudgetSpec::tightened_by], so the stricter cap wins on every dimension;
  • allowlist rules run after the local policy chain, so a call must pass both;
  • schema rules run after the local schema, so arguments must satisfy both;
  • guardrail rules (deny patterns over tool arguments, chat requests or model responses) run after everything local, so they can only refuse;
  • transform rules (redaction of tool arguments or chat requests) run before the verdict, so the rewritten text is what every local gate sees, what is journaled, and what is forwarded.

A compromised console can therefore block calls the host allows, but it can never let through a call the host’s own config refuses.

PushedGuardrail
One pushed guardrail: a set of deny patterns over the text an agent sends. Patterns are compiled with the same bounds as the daemon’s own redaction_patterns ([pv_redact::compile_pattern]).
PushedRules
Everything the daemon applied from one console bundle.
PushedSchema
One pushed argument schema for one tool.
PushedTransform
One pushed transform: every match of its patterns in the text an agent sends is replaced before the verdict is taken, before anything is journaled, and before the call is forwarded. Patterns are compiled with the same bounds as the daemon’s own redaction_patterns.
ToolPattern
A tool-name pattern taken from a policy scope (tool.*, tool.create_payment, tool.payments.*). * matches any run of characters, including none.
