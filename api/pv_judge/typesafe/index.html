pv_judge

TypeSafe’s Jev model as a judge, through its System One API.

Built from TypeSafe’s published reference (docs.typesafe.ai, the OpenAPI document at api.typesafe.ai/openapi.json): one POST /v1/systemone per predicate, with a bearer key.

  • state is the request rendered by crate::render::render_request after redaction: the operator’s context first, the validated arguments last and capped, never the prompt.
  • questions holds one choice question whose options are the predicate’s labels and whose instructions are its description.
  • The answer’s probabilities become the verdict, through the same validation as every other adapter: a missing, extra or duplicate label is a malformed answer, never a partial verdict.

Model pin: TypeSafe names releases (jev-1.14.0) and reports in each answer the versioned id that produced it, but publishes no weight hash. The pin therefore covers the version name only: its weights_sha256 is derived from that name (derived_weights_sha256), a moving alias (jev-latest, jev-preview) is refused, and an answer from any other version fails as a model mismatch. A weight change under an unchanged version name cannot be detected.

This is a second path by which data leaves the harness, like the generic cloud contract: the harness requires a per-tool opt-in and redacts before sending. No request header that widens what TypeSafe accepts (images, long context) is ever sent, and nothing is retried: the runner’s deadline bounds each call.
