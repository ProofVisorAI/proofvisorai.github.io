Module render 

Source
Expand description

The text a local classifier reads for one request.

This rendering is part of the model contract: a model must be trained (or fine-tuned) on text in exactly this layout, so the layout is versioned. Keys are sorted so the same call always renders the same way, and long values are cut at a character boundary before tokenization.

The arguments come last. A model reads at most its token limit, so whatever does not fit is cut from the end: with the operator’s context (intent, task, mission, refusals) first, oversized or padded arguments can only push out the tail of the arguments, never the task the model needs to judge them against.

Longest rendered arguments, in characters.

Most prior denials rendered.
MAX_TASK_CHARS
Longest rendered task, in characters: the tasks of every applicable mission, joined. A longer task is not cut, the request fails instead (request_too_long), since a restriction stated late in it would otherwise go unread.
