Semantic judge integration ([judge]).

The judge runs on /v1/mcp tool calls whose tool is listed under [[judge.tools]], between the schema gate and the policy gate. It sees the schema-validated arguments and operator-controlled context (intent, mission task, charter, delegation depth, and refusals the harness recorded for this session and for the caller’s delegation parents), never the raw prompt. Untagged tools never reach it, so their admission path is unchanged.

The judge never decides. Its verdicts go to the sandbox’s policy gate, where [[judge.thresholds]] (and any WASM ABI v2 policy) turn them into allow, ask (APPROVAL_REQUIRED), or deny, and where every failure denies or asks, never allows. Each verdict, with its full distribution and the pinned model, is written into the tool-call OCSF event (hashed into the signed event chain) and the ATIF tool call (hashed into a retroactive receipt).

State kept in this process: the drift monitor, the review queue and the concurrency limits. The prior-denial log is kept here and, when the state store is shared between instances (Redis), in the store too; the pilot cap counters live in the state store.
