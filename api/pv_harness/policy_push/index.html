Module policy_push 

Source
Expand description

Console-pushed policy bundles.

The daemon never calls the console. pvctl console-sync --watch --pull-policies, running on the same host, pulls the org’s policy bundle (GET /api/v1/ingest/policies) and writes it atomically to the file named by policy_bundle_file. The daemon loads that file at boot and polls it for changes; each new bundle is compiled into pv_sandbox::PushedRules plus token-rate rules and swapped in whole. After every attempt the daemon writes its own answer next to the bundle (<policy_bundle_file>.status.json): the etag it applied, the policy ids it now enforces and the ones it could not enforce, with a reason. pvctl reports that file to the console, so the console’s “Enforced by N of M daemons” reflects what daemons actually run, not what was sent to them.

Pushed rules only add restrictions (see pv_sandbox::pushed). A bundle that cannot be read or parsed leaves the rules already in force unchanged — at boot that means the daemon refuses to start, because running without rules the operator expects to be there would fail open.

Kinds: budget, allowlist, schema (tool calls), rate (per-principal token velocity on model traffic), guardrail (deny patterns over tool arguments, chat requests or model responses) and transform (redaction of tool arguments, chat requests or model responses) are enforced when the body is the JSON spec. A guardrail or transform with a free-text body is reported unsupported with that reason. Anything else is reported unsupported.
