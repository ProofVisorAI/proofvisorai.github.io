Receipt verifier

Verify a session receipt

Drop the receipt a ProofVisor session ended with. Your browser checks its Ed25519 signature against the public key inside it. Nothing is uploaded and no account is needed.

  • Offline The check runs in this tab with Web Crypto.
  • Nothing sent The receipt never leaves your computer.
  • Instant One signature check, about a millisecond.

Drop a receipt JSON here

Drag the file onto this box, paste it with ⌘V / Ctrl+V, or choose it.

No receipt at hand? then tamper with one byte and watch it fail.

How this works

  1. 1

    A session ends with a receipt

    The receipt is a signed JSON that commits to every event, token, tool call and policy decision of the session. It carries the Ed25519 public key that signed it.

  2. 2

    Your browser checks the signature

    Web Crypto verifies the raw signed body against that key. Change a single byte anywhere and the check fails. After a green result, press Now tamper with one byte to see it.

  3. 3

    You confirm who owns the key

    A valid signature proves the receipt was not altered. It does not say who holds the key. Compare the key fingerprint shown above with the deployment page in the console, or with the key the operator gave you.

A green result proves

  • The signed body is byte for byte what the signer produced.
  • The signature was made with the private half of the embedded key.
  • For keys on this page's trust list, or pinned by the console, that the signer is the deployment the console recorded.

It does not prove

  • Who owns an unknown key. Such a receipt is shown as internally consistent, trust anchor not verified.
  • That the events are true. It proves they were recorded and sealed, not that the agent did the right thing.

The same check runs offline in Node, on the same code path: node server/scripts/verify-receipt.mjs receipt.json
